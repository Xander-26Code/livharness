# LivHarness

[English](README.md) | [简体中文](README_ZH.md)

**让 Agent 确认任务是否做好，并在长任务中始终掌握当前目标和重要限制。**

LivHarness 是一个 Python 项目，负责把大模型和工具连接起来，管理 Agent 完成任务的过程。

> **项目还在初级开发阶段。** 目前支持基础文件工具和对话保存。下面两个方向是我们接下来要实现的目标。

## 我们想做出什么

### 1. 确认任务是否做好 — Verified Agent Execution

执行重要操作前，检查文件、参数等条件是否符合预期；执行后，检查结果是否满足任务要求。

例如，修改配置文件后，检查文件能否正常读取、配置值是否正确。对于没有检查过的部分，明确告诉用户。

### 2. 长任务中保持方向 — State-Aware Context Engineering

每次调用模型时，让它知道最新的目标、重要限制、尚未解决的问题，以及文件或环境发生的变化。

例如，用户中途改变要求，Agent 应该按新要求继续；对话变长后，仍然记得“不要修改这个文件夹”；文件被改动后，也知道之前读取的内容可能已经过时。

我们希望根据任务进展选择下一步需要的信息，减少无用历史，同时保留影响后续操作的关键内容。

我们会从本地文件任务开始，验证这些设计能否让任务完成得更好、减少重复操作，并控制成本。

## 现在能做什么

目前的原型支持：

- 与 DeepSeek 对话，让模型调用工具。
- 读取文本、列出目录、查找文件。
- 替换文件中唯一匹配的文本。
- 使用 `pypdf` 提取 PDF 文字，不支持 OCR 或图片理解。
- 保存对话、加载历史会话、查看最近的会话。

上面的两项核心能力还在规划中。目前加载会话恢复的是已保存的消息，不能准确恢复任务中断时的执行状态。

## 版本路线图

每个版本都对应一组具体功能。以下是开发目标，尚未作为正式版本发布，也没有确定发布日期。

| 版本 | 重点 | 计划交付的功能 | 当前状态 |
| --- | --- | --- | --- |
| **v0.1** | Harness 基本功能 | 模型调用、工具注册与执行、文件工具、多轮对话、会话保存与加载 | 已有原型和首批编辑测试，待补其他测试 |
| **v0.2** | 终端界面与工具结果 | 交互式终端界面（TUI），分开展示对话、工具调用和运行状态；结构化工具结果，统一返回成功或失败、内容和错误信息 | 计划中 |
| **v0.3** | 检查任务结果 | 在重要操作前检查条件，操作后验证结果，记录哪些通过、哪些失败、哪些还未验证 | 计划中 |
| **v0.4** | 长任务中保持方向 | 跟进最新目标，保留重要限制和未解决的错误，刷新过时文件信息，减少无用历史 | 计划中 |
| **v1.0** | 串起完整流程 | 在本地任务中整合界面、工具、结果检查和上下文管理，提供可重复运行的评测，说明支持范围 | 计划中 |

当前界面还是简单的文字输入输出，TUI 和结构化工具结果是 v0.2 要做的内容。中断恢复保留为后续改进，等批量处理等长任务有实际需要时再确定范围。

我们计划使用相同任务和模型，对比不同版本的实际成功率、错误完成报告、是否遵守最新要求、耗时和 token 用量。目前还没有评测结果。

## 快速开始

需要 Git、Python 3.10+，以及能够访问当前配置模型的 DeepSeek API Key。

```bash
git clone https://github.com/Xander-26Code/livharness.git
cd livharness
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

如果你的 Python 3.10+ 解释器使用其他命令，请替换上面的 `python`。Windows PowerShell 使用 `.venv\Scripts\Activate.ps1` 激活环境。

### 配置

在项目根目录创建 `.env` 文件：

```dotenv
DEEPSEEK_API_KEY=replace_with_your_own_key
```

当前模型配置为 `deepseek-flash`。模型名称和 API 地址可在 [agent_loop.py](agent_loop.py) 中修改。不要提交自己的密钥；Git 已忽略 `.env`。

在仓库根目录启动：

```bash
python main.py
```

可以试着输入：`请读取 tools/read_file.py，解释它做了什么。`

**请先使用测试文件或副本。** 当前程序直接修改文件，没有沙箱或自动回滚。文件内容可能发送给模型服务，模型调用会使用你的 API 账户。

## 使用方式

| 命令或输入 | 作用 |
| --- | --- |
| `python main.py` | 开始新对话 |
| `python main.py --list-sessions` | 查看已保存的会话，最近更新的在前 |
| `python main.py --resume SESSION_ID` | 加载历史对话；将 `SESSION_ID` 替换为实际会话 ID |
| `/clear` | 清空当前对话，已经修改的文件不会恢复 |
| `exit` 或 `quit` | 退出 |

`/clear`、`exit` 和 `quit` 在 `User:` 提示后输入。运行 CLI 前需要配置密钥，包括查看会话列表时。

欢迎从一个小问题开始：

- **刚开始参与：**完善文档、提供能复现的 Bug，或给文件工具补测试。
- **v0.2：**一起制作终端界面，或设计统一的工具结果格式。

- **上下文管理：**设计需要跟进新要求、记住限制、发现文件变化的任务案例。

目前有四个初始测试，检查正常替换、拒绝重复匹配、会话保存与加载，以及工具参数 JSON 错误时不执行工具并返回结构化错误。安装项目依赖后，在仓库根目录运行，不需要密钥，也不会调用真实模型：

```bash
python -m unittest discover -s tests -v
```

其他工具、会话测试和 CI 仍待补充。代码入口是 [main.py](main.py)，Agent 循环在 [agent_loop.py](agent_loop.py)，工具在 [tools/](tools/) 中。
